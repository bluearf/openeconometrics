# Installed Windows collaboration acceptance

The `windows-email-cloud.yml` manual workflow installs bytes from a successful, immutable Windows producer run. It verifies the accepted installer SHA256 and each installed resource hash. The controller and installer source commits remain separate in receipts. A build or source-fixture pass alone is not native acceptance.

Only a disposable GitHub-hosted Windows administrator is admitted. Owner and viewer use distinct actual Roaming/Local KnownFolders and WebView2 profiles. Exact executable policies and process creation times attribute the loopback debugger to the installed native app. Original KnownFolders, firewall profile states and exact owned debug policies are restored; cleanup never kills unrelated processes or deletes user projects.

Authentication uses actual six-digit email codes. No password, Firebase administrator credential, user token or Google account is sent to the runner. The runner creates an ephemeral RSA key; its public key, run ID and random nonce are published as a bounded artifact. A temporary private-repository QA branch carries only authenticated encrypted packets. AES-GCM protects each payload; RSA-OAEP protects its random key. Every delivery binds run, nonce, challenge, purpose, role and expiration. The runner's read-only GitHub token is passed only to the exact Node controller, never to the native app or frozen numerical worker. Private keys and fixture manifests are destroyed during cleanup. Temporary mailbox branches are removed after the run. Codes and raw authentication inputs never enter logs or artifacts.

| Phase | Actual installed behavior required |
| --- | --- |
| `email-request-owner` | Fresh normal email form and code request, bound to this native profile and one-run challenge. |
| `email-open` | Enter the real received code, verify normal sign-in, then fresh authenticated `/api/me` UID/email/owner membership before and after opening the exact owned project. No computation. |
| `offline-run` | Actual outbound Internet block for the installed app and frozen runtime, with loopback retained. Native broker network failure; one local 480-observation HC3 OLS, model and publication LaTeX, stdout and ordered events, one pending outbox record, execution counter one. |
| `offline-reopen` | Actual graceful process exit and cold restart under the same block/profile. Original ID/model/LaTeX/events unchanged; manual Retry remains pending; no refit. |
| `retry-online` | Remove exact owned block rules and verify restoration. Fresh authenticated owner membership, native reconnect and original record delivered once. Empty outbox, unchanged result, no refit. |
| `email-request-viewer` | Distinct canonical native root and filesystem identity before reading the private fixture; fresh normal email-code request for the viewer. |
| `viewer-readback` | Real code verification and fresh authenticated viewer membership. Disabled terminal and actual Shared history search/open; the original model, LaTeX, stdout and event digest match. No local or cloud computation. |

Each phase has a fresh exclusively created receipt. Canonical path, junction, case and inode aliases cannot overwrite its protected manifest, email challenge or original proof. Native root identities are checked before credentials and again after the phase. The original offline receipt binds the immutable original online receipt hash. Offline identity is explicitly cached; it does not claim fresh live authentication.

The transport observer faithfully wraps and restores existing IPC/fetch, without changing responses, tokens or calculations. It observes ordered real `/api/me` responses and refuses stale, denied, missing, duplicated or foreign memberships. A matching visible email does not certify identity. Native broker connectivity is checked independently of WebView2, so browser-only offline emulation cannot pass.

Scientific fixture validation checks the complete saved model separately from display summaries. Archive comparisons preserve all numbers, covariance/sample evidence, publication and ordered output; only documented omission-label ordering is normalized. Retained failed receipts remain failures. A separate cloud readback must verify archive uniqueness, zero cloud computations and owned-resource cleanup; controller observations alone do not certify server state. Google-provider acceptance is separate from this email-code workflow.
