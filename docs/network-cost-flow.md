# Minimum-cost and multicommodity flow

`Network.min_cost_flow(demands, costs, ...)` solves one directed commodity.
`Network.multicommodity_flow(commodities, costs, ...)` solves fractional,
splittable commodities with a shared capacity on each coalesced directed edge.
The methods use native CPU Torch float64 two-phase simplex with Bland pivots.
No external LP library is required at runtime. This is a bounded dense-tableau
solver, intended for admitted small/medium flow problems.

```python
graph = oe.network([
    {"source": "s", "target": "a", "capacity": 3},
    {"source": "a", "target": "t", "capacity": 3},
    {"source": "s", "target": "t", "capacity": 2},
], directed=True, weight="capacity")
flow = graph.min_cost_flow({"s": -4, "t": 4},
                          {("s", "a"): 1, ("a", "t"): 1, ("s", "t"): 5},
                          domain="integral")
assert flow["status"] == "optimal" and flow["objective"] == 11
print(flow["flows"])
```

Positive demand means required net inflow; negative demand supplies flow.
Unmentioned nodes have zero demand. Demand imbalances are diagnosed as
infeasible, without normalization. Costs are finite values for every retained
arc, supplied by `(source, target)` mapping or coalesced edge order. Multiple
commodities may use one shared cost vector or a mapping from commodity names
to separate vectors. Capacity defaults to graph weight; overrides admit zero
and positive infinity. Infinite capacity must be chosen explicitly. Typed
integer and string node IDs remain distinct. Parallel arcs must first be
explicitly projected to a coalesced `Network`; multigraph/disk/signed objects
and undirected networks are rejected.

| Domain/status | Contract |
| --- | --- |
| `domain='fractional'` | single or multiple commodities, splittable nonnegative flows |
| `domain='integral'` | single commodity only; integral demands/finite capacities within 2^40, checked integral point |
| `optimal` | feasible flows, primal objective, dual multipliers, reduced-cost and duality-gap checks |
| `infeasible` | no flows; Farkas multipliers with `A' y <= 0` and `b' y > 0` |
| `unbounded` | feasible point and nonnegative conservation-preserving improving ray |

The standard form is `min c'x`, `Ax=b`, `x>=0`, with commodity-major node
balances and finite-capacity slack equations. Certificate metadata records
that order and the node/commodity/edge labels so callers can independently
reconstruct A, b and c. Optimality checks use absolute 1e-7 primal residuals
and relative 1e-7 objective/cost scale. Numerically uncertified problems raise
`network_precision_unsupported` rather than return a purported solution.
Finite negative-cost circulations are optimized. An unlimited improving
circulation returns `unbounded`. Nonzero cost dynamic range above 1e8 is
rejected; float64 is not an exact-arithmetic proof.

Defaults: `max_entries=1_000_000`, `max_work=50_000_000`,
`max_pivots=10_000`. Admission checks the conservative tableau size before
allocation and the graph's owned-memory budget. Work counts the admitted
cells plus twice the current tableau cells per pivot; it is a deterministic
budget proxy, not CPU instructions or process RSS. Exceeding any budget
raises explicitly, without a truncated solution. Integer multicommodity
optimization is not implemented, and no general fast integer solver is claimed.

The result exposes `.summary()` and `.to_latex()`; `display(flow)` presents a
compact summary in the code panel. Paste [the five-method example](examples/five_more_issues.py)
into an OpenEconometrics code panel to run the flow and econometrics additions
on synthetic data. Existing max-flow/min-cut methods retain their own sparse
algorithm and certificates.

Tests independently enumerate small integral optima, compare fractional LPs
with HiGHS (development oracle only), verify all certificates, exercise finite
and unlimited negative cycles, and preserve max-flow behavior. The scale
measurement is generated by `scripts/benchmark_cost_flow.py`; exact dimensions,
budgets, time and certificate residuals are in the accompanying evidence.
